onebox is starting in namespace {{ .Release.Namespace }}.

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "onebox.fullname" . }}

Console and API (one port):
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "onebox.fullname" . }} 8080:{{ .Values.service.port }}
  open http://localhost:8080/v2

SDK / CLI endpoint: dns:///localhost:8080 (insecure) through the port-forward,
or the address of the authenticating proxy you put in front of the Service.

{{- if .Values.authz.enabled }}

Authorization is ON. Requests need identity headers ({{ first .Values.identity.subjectHeaders }}):
expose the Service only through your authenticating proxy.
{{- if and (not .Values.identity.proxySecret.existingSecret) (not .Values.networkPolicy.proxyFrom) }}

WARNING: neither identity.proxySecret nor networkPolicy.proxyFrom is set, so
any pod that can reach port {{ .Values.service.port }} can claim to be any user. Set one of them.
{{- end }}
{{- if eq (toString .Values.networkPolicy.enabled) "false" }}

WARNING: networkPolicy.enabled=false. Every request on the in-cluster tasks
port (8082) acts as the tasks app (role {{ .Values.authz.tasksRole }}); without the
NetworkPolicy any pod in the cluster can reach it.
{{- end }}
{{- else }}

Authorization is OFF: anyone who can reach the Service can do anything.
Requests are attributed to the user in {{ first .Values.identity.subjectHeaders }} when present.
{{- end }}
